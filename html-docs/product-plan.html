销售助手Agent 产品方案

面向工程行业的 Agent Native 文档任务产品设计。

工程行业文档 Agent 产品方案

1. 产品定位

本产品面向建筑、基建、装备制造、能源、轨道交通、化工、电力、矿山、水利、涂料等工程行业，提供 Agent Native 的工程文档任务能力。

2. 用户与价值

用户角色典型目标主要产品价值
一线工程技术人员写方案、指导书、技术说明，查标准和资料降低编写和查证成本，减少模板套用错误
项目交付与资料人员检查资料缺口，整理交付包，追踪异常资料提高资料完整率，减少交付前集中补资料
技术销售与解决方案人员生成解决方案、推广材料、技术答复快速把产品/设备资料转化为客户可用材料
企业知识与标准负责人维护模板、规则、标准、行业包和知识源约束 Agent 输出，保证可追溯和可复核
管理员/实施人员配置集成、权限、行业包、知识源让产品接入既有系统并符合企业权限边界

4. 我的项目与项目上下文

系统权限负责控制用户能看到哪些项目、资料源、知识库和交付物；“我的项目”只是把这些权限结果以项目列表的方式呈现。

用户侧建议展示：

  • 最近访问。
  • 我参与的。
  • 我创建的。
  • 已收藏。
  • 全部项目（按权限）。

项目详情页保持轻量：

模块内容
项目概览项目名称、行业、阶段、客户/场景、最近更新时间
项目资料上传文件、引用资料源、关联知识库
Agent 任务查找、生成、计算、审核任务记录
交付物PPT、Word、Excel、审核报告、缺口清单
项目设置基础信息、资料范围、行业场景包、权限继承

项目上下文是 Agent 执行任务时真正使用的上下文，包含：

  • 当前项目。
  • 行业场景包。
  • 工程对象。
  • 可引用资料范围。
  • 输出归属。
  • 权限约束。
  • 已确认的参数、风险项和引用依据。

5. 四类能力设计

5.1 能力总览

能力用户问题典型任务主要输出
查找资料在哪里，依据是什么，有没有相似案例标准规范查找、设备资料定位、历史案例检索、相似方案复用资料列表、引用依据、相似案例、定位结果
生成如何快速形成可交付文档方案生成、作业指导书、技术说明书、推广材料、交付报告Word、PPT、PDF、报告初稿、证据包
计算数值是否合理，工程量/用量/完整率是多少材料用量估算、工程参数计算、资料完整率计算、版本差异统计计算结果、过程说明、参数来源、异常提示
审核是否满足要求，是否缺失，是否有风险技术符合性审核、资料缺口审核、设备资料完整性审核、变更影响审核审核矩阵、缺口清单、风险清单、补件建议

四类能力不是割裂的。一个完整任务经常会串联多个能力：

  • 生成方案前，先查找产品资料、标准规范和历史案例。
  • 生成方案后，计算材料用量、工程量或关键参数。
  • 交付前，审核资料完整性、引用依据和风险项。
  • 审核发现缺失后，反向触发查找或生成补充材料。

5.2 任务执行页

任务执行页不是普通聊天页，也不是结果页，而是单次 Agent 任务的作业台。它负责把“任务目标、项目上下文、资料引用、Agent 执行过程、人工确认、结果审阅、导出回写”串成一个可追溯的闭环。

任务执行页的作用：

  • 上下文确认：确认当前项目、行业场景、资料范围、输出格式。
  • 资料引用：选择项目资料、知识库、API 查询结果、本地上传文件。
  • 过程透明：展示 Agent 正在查找、解析、生成、计算或审核什么。
  • 人工介入：对缺失信息、风险项、关键参数和假设条件进行确认。
  • 结果审阅：审阅大纲、正文、计算结果、审核矩阵或缺口清单。
  • 交付回写：导出 Word/PPT/PDF/Excel，或推送到企业微信、邮件、网盘、API。

任务执行页结构：

左侧：任务上下文

  • 当前项目
  • 项目上下文
  • 行业场景包
  • 工程对象
  • 已上传资料
  • 已引用资料源
  • 已选模板
  • 输出格式

中间：Agent 执行区

  • 正在解析资料
  • 已识别关键对象
  • 已提取关键参数
  • 已生成大纲
  • 待确认问题
  • 正文生成中
  • 审核矩阵生成中
  • 缺口清单生成中

右侧：结果与风险

  • 输出文档
  • 引用来源
  • 风险提示
  • 缺失信息
  • 需人工确认项
  • 导出 Word/PPT/PDF/Excel
  • 回写到集成系统
  • 任务记录与版本

7. 行业场景包

行业场景包是对同一套 Agent 底座的行业化配置，不是为每个行业做一套独立软件。

每个行业包包含：

  • 行业术语库。
  • 工程对象模型。
  • 文档模板。
  • 资料目录规则。
  • 标准规范映射。
  • 审核规则。
  • Agent 工作流。
  • 输出格式。

行业包优先级：

优先级行业产品理由
第一梯队涂料、装备制造、电力设备、化工设备文档生成价值强，产品/设备资料相对可结构化，销售和交付都有需求
第二梯队能源、电力、轨道交通、化工交付资料和合规审核价值高，但行业门槛更高
第三梯队建筑、基建、水利、矿山资料量大，但现场数据更脏、流程依赖更重

行业包示例：

行业包关键对象高频任务
涂料底材、环境、涂层体系、TDS/SDS、检测报告、施工工艺解决方案生成、施工指导书、推广材料、技术符合性审核
装备制造设备、部件、BOM、图纸、检验规程、说明书、维护手册技术方案、说明书、检验规程、设备交付包

轨道交通系统接口、规格书、联调联试、验收资料接口文件审核、技术符合性审核、调试验收资料

8. 工程知识底座

工程知识底座不是普通文件夹或通用知识库，而是面向 Agent 任务的工程对象化知识层。

核心对象：

  • 项目。
  • 专业。
  • 系统。
  • 设备。
  • 材料。
  • 产品。
  • 标准。
  • 工艺。
  • 图纸。
  • 检测报告。
  • 施工记录。
  • 验收资料。
  • 历史案例。

使用原则：

  • 普通用户不直接维护知识底座，只在任务中引用资料源。
  • 专家和管理员维护知识源、规则、模板和行业包。
  • Agent 输出必须保留引用来源和可追溯路径。
  • 项目上下文中的确认结果可以沉淀回知识底座，但需要人工审核。

9. 文档解析与多格式输入

必须支持的输入：

  • Word。
  • Excel。
  • PDF。
  • PPT。
  • 扫描件 OCR。
  • 图片。
  • CAD/PDF 图纸索引。
  • P&ID 初步索引。
  • 表格抽取。
  • 文件元数据识别。

重点识别内容：

  • 文件类型。
  • 文件编号。
  • 版本。
  • 日期。
  • 签章状态。
  • 标题栏。
  • 页眉页脚。
  • 表格字段。
  • 设备位号。
  • 材料/产品型号。
  • 标准条款。
  • 检测结论。

10. 集成中心

集成中心是轻量连接器，不是重型系统集成平台。当前阶段重点是让 Agent 能从外部拿数据、向外部推消息、把结果回写出去。

优先集成类型：

优先级集成类型产品用途
P0企业微信/飞书/钉钉发起任务、推送待确认项、补件提醒、发送交付物链接
P0API 查询查询产品参数、标准条款、项目资料、设备台账、物料/BOM、历史案例
P0文件源读取用户上传文件、企业网盘、对象存储、知识库目录
P1输出回写回写到企业微信、邮件、网盘、对象存储、自定义 API
P1Office/WPS 导出生成 Word、PPT、Excel、PDF
P2工程系统连接按客户需要接入 PDM/PLM、EAM/CMMS、DMS、CDE 等

API 查询配置项：

配置项说明
API 名称产品资料查询、设备台账查询、标准条款查询
请求方式GET/POST
鉴权方式API Key、OAuth、企业内部 Token
输入字段产品型号、项目编号、设备编号、标准编号
返回字段映射参数名、单位、来源、更新时间、置信等级
可用任务查找、生成、计算、审核
权限范围哪些角色、项目、行业包可调用
失败处理超时、无结果、字段缺失时的提示策略

集成原则：

  • 优先读现有系统，不强制迁移。
  • 优先做任务级调用，不重做原系统功能。
  • 在任务页只暴露“可引用资料源/API”，隐藏复杂配置。
  • 生成结果支持导出、消息推送和 API 回写。
  • 保留来源链接、调用记录和权限边界。

11. 配置中心

配置中心用于管理模板、行业包、规则和知识源。配置必须支持自定义，但应按权限分层：平台默认配置、企业级自定义、项目级轻量覆盖、任务级临时选择。

11.1 模板配置

模板包括结构模板、内容模板和输出模板。

模板类型示例用途
PPT 模板产品方案 PPT、项目汇报 PPT、技术交流 PPT控制页面结构和视觉样式
Word 模板作业指导书、施工方案、审查报告控制章节结构
Excel 模板符合性矩阵、资料缺口清单、设备参数表控制表头和字段
内容模板风险提示、施工步骤、产品推荐理由控制专业表达
交付包模板竣工资料目录、设备移交目录控制资料清单结构

可自定义内容：

  • 模板名称。
  • 适用行业。
  • 适用任务。
  • 章节结构或页面结构。
  • 字段占位符。
  • 样式规范。
  • 必填内容。
  • 引用格式。
  • 导出格式。

应用方式：

  • 系统根据行业包和任务类型推荐模板。
  • 用户在任务执行页选择或切换模板。
  • Agent 按模板生成大纲、正文、表格或 PPT 页面。
  • 缺少必填字段时，Agent 追问用户或标记缺失。

11.2 行业包配置

行业包是让 Agent 理解行业语境的配置集合。

配置项示例
行业术语C5-M、P&ID、FAT/SAT、继保、检验批
工程对象产品、设备、系统、管线、涂层体系、分部分项
文档类型TDS、SDS、设备说明书、试验报告、竣工图
默认模板涂装方案 PPT、设备移交清单、作业指导书
默认规则参数必须溯源、外发案例需授权、缺依据需确认
示例任务生成沿海钢结构防腐方案、检查设备资料缺口

自定义方式：

  • 平台提供基础行业包。
  • 企业管理员可复制行业包并自定义。
  • 项目/任务层只允许选择行业包和少量覆盖，不建议普通用户修改行业核心规则。

应用方式：

  • 用户选择行业场景。
  • Agent 加载术语、对象、文档类型、默认模板和默认规则。
  • 查找、生成、计算、审核都按该行业包执行。

11.3 规则配置

规则用于约束 Agent 行为和结果质量。

规则类型示例
数据来源规则产品参数必须来自产品库、TDS 或 API
引用规则技术结论必须带来源文件和页码
生成规则缺少依据时不得生成确定性结论
审核规则VOC 超过客户要求时标记不符合
权限规则内部案例不能用于客户外发 PPT
风险规则涉及寿命、质保、安全必须人工确认
格式规则审查报告必须输出“符合/不符合/需确认”
计算规则材料用量必须显示公式、参数和假设

规则层级：

层级谁能改示例
平台规则产品团队通用溯源、权限、安全规则
企业规则企业管理员/专家产品参数来源、外发限制、模板规范
行业规则行业专家/管理员涂料、电力、化工等专业规则
项目规则项目负责人本项目资料目录、客户特殊要求
任务规则普通用户本次输出页数、语言、格式、侧重点

应用链路：

任务创建
→ 选择行业包
→ 选择模板
→ 读取项目上下文
→ 调用知识库/API
→ 执行规则校验
→ 生成中间结果
→ 标记风险
→ 人工确认
→ 输出交付物

11.4 可追溯生成

生成内容分两类：

  • 事实内容：必须来自资料库、标准、产品资料、历史文档或人工确认。
  • 表达内容：允许 Agent 重组、润色、扩写。

输出文档应保留：

  • 引用来源。
  • 可信度。
  • 需人工确认项。
  • 缺失信息。
  • 风险提示。
  • 生成时间和任务记录。

12. 人机协同审阅

Agent 不替代专家审批，只承担初稿生成、自动初审、资料整理和风险提示。

关键能力：

  • 高风险内容标红。
  • 缺失条件追问。
  • 引用来源查看。
  • 专家批注。
  • 人工确认后再生成。
  • 版本对比。
  • 审核矩阵导出。
  • Word/PPT/PDF/Excel 导出。
  • 任务结果回写。
