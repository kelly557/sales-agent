工程行业销售 Agent 端到端流程与数据流设计

01. 设计目标与边界

目标是表达一个工程行业销售 Agent 从销售输入到客户方案交付的端到端流程，重点是数据如何进入、被理解、被检索、被组织成证据包、被填入行业模板并回写记忆。能力模块是执行节点，不是本文档的主角。

目标

A一个 Agent 多行业包

同一个销售 Agent 通过行业包适配建筑、涂料，后续扩展化学、材料等工程行业。

B表单按行业配置

表单字段由行业包和租户配置生成，支持必填、推荐、可选、隐藏和上下文预填。

C数据流是核心

关键不是展示能力名称，而是说明每一步消耗什么数据、产出什么数据、如何传递到下一步。

D输出必须可追溯

客户方案中的产品、案例、价格、用量、服务承诺和方案依据都要保留来源、版本和权限标签。

这个样例体现建筑行业销售的真实数据特点：客户项目机会、工程范围、历史案例、企业资质、服务能力、初步工程量、报价边界和交付承诺。

10. 校验、输出与回写

能力执行完成后可以出结果，但不能跳过校验。校验不是额外对话，而是结果包装的一部分。

Validation

V版本校验

建筑图纸、规范、做法表、产品说明书、检测报告必须检查版本。命中新旧冲突时只输出最新有效版本，并提示冲突来源。

P权限校验

跨项目资料、内部价格、成本、未公开检测报告、客户信息必须按 SaaS 租户和角色过滤。

R适配校验

建筑检查专业/部位/工序是否匹配；涂料检查产品、基材、环境、体系和施工条件是否匹配。

Q表达校验

避免“保证不脱落”“永久防水”“完全环保”等绝对承诺，替换为有条件的工程表达。

建议落地口径：查询任务返回“答案 + 来源 + 适配说明 + 待确认项”；生成任务返回“正文 + 内部依据 + 假设条件 + 风险提示 + 可导出格式”。这样产品、开发和算法都能围绕同一输出契约迭代。
