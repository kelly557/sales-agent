01 产品定位

POSITION

不是文档管理系统，而是工程文档任务 Agent

以“我的项目”作为轻量项目入口，以“项目上下文”作为 Agent 执行任务时的资料范围和输出归属，连接既有资料源，围绕查找、生成、计算、审核组织任务。

02 用户与使用目标

USERS

一线工程技术人员

写方案、指导书、技术说明，查标准与资料，减少模板套用和依据遗漏。

项目交付与资料人员

检查资料缺口、整理交付包、追踪异常资料，减少交付前集中补件。

技术销售与方案人员

把产品、设备、案例资料转化为客户可用的方案、PPT 和技术答复。

知识/标准/实施人员

维护模板、规则、行业包、知识源、权限与集成，约束 Agent 输出质量。

04 行业场景与行业包

SCENARIOS
第一梯队涂料 / 装备 / 电力设备 / 化工设备文档生成价值强，产品和设备资料相对可结构化，销售与交付均有需求。
第二梯队能源 / 电力 / 轨交 / 化工交付资料和合规审核价值高，但行业门槛、规则复杂度和实施深度更高。
第三梯队建筑 / 基建 / 水利 / 矿山资料量大、任务高频，但现场资料更脏，流程依赖和客户集成要求更重。
行业包内容术语 / 对象 / 文档类型 / 规则行业术语、工程对象、文档类型、默认模板、默认规则和 Agent 工作流。
典型对象设备 / 材料 / 图纸 / 报告底材、涂层体系、BOM、P&ID、定值单、接口文件、检验批、验收资料。

06 核心机制：我的项目 + 项目上下文 + Agent 任务引擎

CORE MODEL

我的项目

最近访问、我参与的、我创建的、已收藏、全部项目按权限呈现。

轻量集成中心

企业微信/飞书/钉钉、API 查询、文件源、输出回写和 Office/WPS 导出。

项目上下文

当前项目、行业场景、工程对象、资料范围、输出归属和权限约束。

配置中心

模板、行业包、规则、知识源、集成配置、用户权限和分层覆盖。

Agent 任务引擎 规划步骤、检索证据、调用工具、生成结果、标记风险。
任务输入

输入任务、上传资料，选择我的项目、行业、模板和输出格式。

执行过程

引用项目资料、知识库、API 查询结果和本地上传文件。

人工确认

风险、缺失、冲突、低置信内容进入人工复核队列。

交付沉淀

导出 Word/PPT/PDF/Excel，进入我的交付物并沉淀案例与规则。

07 端到端任务执行流程

WORKFLOW
01

进入首页

选择“我的项目”中的项目，或创建轻量项目后输入任务。

02

形成上下文

确认当前项目、行业场景、工程对象、资料范围和输出归属。

03

解析资料

识别文件类型、编号、版本、签章、表格字段和关键参数。

04

执行任务

查找依据、生成正文、计算参数、形成审查矩阵。

05

提示缺失

发现缺少条件或资料时追问用户并回到资料选择。

06

审阅确认

人工查看引用、风险、缺口和需确认项，必要时重跑。

07

导出回写

输出可编辑交付物，推送消息或通过 API 回写外部系统。

08

资产沉淀

将结果沉淀为项目资产、案例、模板、术语或规则。

11 落地路线

ROADMAP

阶段 1：可用任务闭环

  • Agent 首页与我的项目
  • 方案/指导书生成
  • 标准与资料引用
  • Word/PDF 导出

阶段 2：交付与审核

  • 资料缺口审核
  • 设备资料完整性
  • 审查矩阵导出
  • 消息推送/API 回写

阶段 3：行业化扩展

  • 配置中心分层覆盖
  • 规则与模板运营
  • 变更影响审核
  • 案例沉淀复用

12 交付物与输出格式

DELIVERABLES
DOC
方案 / 指导书 / 报告可编辑正文、章节结构、依据引用、需确认项。
PPT
解决方案 / 推广材料客户场景、产品资料、案例、优势与证据包。
XLS
计算表 / 审核矩阵参数来源、计算过程、风险等级、引用页码。
ZIP
交付包 / 补件清单目录结构、缺失资料、异常资料和补件建议。
